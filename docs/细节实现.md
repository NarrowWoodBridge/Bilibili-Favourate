# 实现备忘

本页保留维护阶段需要持续确认的设计约束。已确认的运行行为放在[架构](architecture.md)和[模块 API](api.md)，可复现风险统一记录在[已知问题](known-issues.md)。

## 身份与去重

- 普通视频应以 `bvid` 作为主要身份，标题只用于显示和默认文件名。
- 多 P 视频需要使用 `bvid + page` 或 `cid` 区分分 P，不能只用 `bvid`。
- 合集需要保存稳定的合集 ID；仅按标题合并无法处理同名合集。
- 视频在收藏夹之间移动或重复收藏时，应明确是共用笔记、复制笔记还是保留来源映射。

## 文件与用户内容

- 用户可能修改文件名，但 YAML `title` 应继续保存视频原标题。
- 合集内默认文件名采用合集条目的显示标题，而不是视频详情原标题。
- 更新笔记时应保留未知 YAML 字段、`# 视频` 区的用户内容和完整 `# 笔记` 区。
- “移动”操作应优先移动原文件并做最小修改，避免删除后重建造成属性丢失。
- Markdown 分段应匹配规范标题行，并对缺失、重复或降级标题给出明确错误。

## 后续重构建议

1. 把模块顶层副作用移入受保护的 CLI 入口。
2. 分离配置解析、API 客户端、领域模型和文件写入。
3. 用稳定 ID 建立索引，标题只作为可变元数据。
4. 为写入操作加入预演、备份或原子替换。
5. 为配置解析、标题清洗、Markdown 往返和合集状态迁移补充自动化测试。
